# 2.11.0 AKShare 行情渠道

本版接入固定版本 AKShare 1.19.1，通过其 SDK 获取公开行情。管理员可在「独立管理台 → 数据源」启停 AKShare，并调整各资产分类的查询顺序；无需配置 Token。正常记账、定投设置与个人资金来源保持原有方式。

## 接入范围

| 产品 | 本版能力 | 数据依据 |
| --- | --- | --- |
| 境内人民币普通基金、QDII | 正式单位净值及历史净值 | 东方财富；保留净值归属日期 |
| A 股 | 已完成交易日收盘价及历史 | 东方财富；不复权，核对证券代码 |
| 境内 ETF | 已完成交易日收盘价及历史 | 东方财富；不把场内收盘价当场外基金净值 |
| 上市商品期货 | 带来源日期和时间的参考行情 | 新浪；不充当机构权益或结算盈亏 |
| 上市商品期权 | 已完成交易日收盘价及历史 | 新浪；先核对上市合约 |

本版没有接入 AKShare 的全部接口。货币基金万份收益、外币份额、港美证券、连续期货、个人账户持仓、实际扣款与成交确认不在新增能力中。原有其他来源仍按既有能力使用。

## 来源、日期与失败处理

- AKShare 是查询渠道，底层发布方单独记录为「原始来源」。AKShare 与原有东方财富基金渠道同日一致，只算一个独立来源；出现差异仍隔离该净值日，不能用两个同源渠道解除隔离。
- QDII 正式收益继续归到净值日；查询时间不替代公布时间或净值日。来源未给出公布时间时显示「来源未提供」。
- A 股、ETF 和商品期权新增渠道使用完成交易日的收盘价，不冒充盘中实时价或结算价。交易日未完成、日期不明、产品身份不符、无效或零价格均不进入正式价格。
- 失败、超时、不可用时继续尝试其他启用且兼容的渠道；已有可用价格保留，不补零。没有可用行情时可继续手工录入账目。
- 新版配置为 `schema_version: 3`。升级旧配置时在适用分类末尾添加 AKShare，保留现有顺序及明确关闭状态；已明确清空或关闭全部配置链的分类不自动重启。新版允许移除 AKShare 或关闭它。

## 实现与运行

SDK 在独立子进程中执行，接口和参数有固定白名单，不接受自定义 URL、函数名或表达式。选定接口的网络请求限制到固定 HTTPS 域名，禁止重定向，限制超时及原始响应大小。子进程使用精简环境，不继承数据库、应用密钥或订阅 Token；单次 SDK 调用最多 20 秒，整次行情操作最多 30 秒，每进程最多两个 SDK 子进程，输出最多 2 MiB。公共行情缓存按产品身份、操作和日期范围区分，不缓存用户名称、空间、账户或私有账单。

期货夜盘若仅提供时钟及交易日，保留 `source_clock` 并说明自然日期尚未核实，公布时间留空，不按刷新时间补造时间戳。

基金历史使用返回 JSON 的 `fund_etf_fund_info_em` 净值接口，核实可返回普通基金及 QDII 后复用；不调用需要执行供应方 JavaScript 的 `fund_open_fund_info_em`。Linux 发布依赖固定到完整版本锁文件，新增构建依赖的来源及轮子哈希保存在发布验收记录。

## 操作

1. 管理员进入「独立管理台 → 数据源」，查看 AKShare 对各分类的能力、启用状态和顺序。
2. 用户进入「分析复盘 → 行情与结算 → 自动行情」更新行情。
3. 展开来源详情，查看查询渠道、原始来源、净值归属日、获取时间及备用查询结果。基金的「单一来源」指单一独立发布方。

公开行情只参与价格与推算，不能证明个人交易成功。需要核对实际扣款、份额或费用时，继续使用实际机构记录。
