# Wealth 开发路线、验收与开工门槛

维护日期2026-10-13。§1–6保留2026-09-16阶段路线和A01–29原验收意图，不能再理解为应用尚未开发；费用/自动定投/日期的现行口径由[domain-model§12–16](domain-model.md)替代原建议。§7–8保留2026-10-09阶段验收事实，§9为2.14.2候选补足能力验收要求；[开发状态](development-status.md)分别记录实现/验证/部署，历史发布不能代替当前测试。

## 1. 交付路线

先把账本和证据链做对，再扩展投资和规划。境内、港美股与多币种从 G1 的基础模型进入，不在后期补改人民币单币账本。每个阶段都交付可演示页面、可重复案例和差异说明。

| 阶段 | 交付内容 | 对应需求 | 放行条件 | 初步开发工作量 |
| --- | --- | --- | --- | --- |
| G0 范围与技术验证 | 样本登记、产品身份、核算政策、Sure 对照、栈兼容性、数据模型与契约 | 全部基础 | 关键未知已分类；能说明底座选择与真实导入格式；核心案例可验证 | 5–8 人日 |
| G1 多家庭与账本骨架 | 邀请登录、角色与隔离、账户、期初、原币金额、实际事件、冲正、审计；电脑端页面框架 | FR-01/02/04/05 | A01–A05、A17 的本阶段入口通过；A19 完成基础账本备份恢复 | 15–22 人日 |
| G2 导入与收支闭环 | 喵喵、支付宝、微信及首个银行样本的适配；原始证据、映射、归并、预览、确认、撤销与现金对账 | FR-03/04/11 | A06–A09、A18 通过；一组真实脱敏月账完整对上 | 20–30 人日 |
| G3 投资与跨市场 | 广发／易方达基金，QDII、定投实际执行，境内／港美股票和外币；广发／银河期货机构结算；收益与持仓对账 | FR-05/06/07/08/11 | A10–A16、A23–A25、A27/A29 通过；五个首批来源覆盖有记录 | 25–40 人日 |
| G4 目标、贷款与现金流 | 大额目标、互斥方案、预留金、贷款计划、到期待办、账单匹配、周期任务 | FR-08/09/10 | A20–A22、A26/A28 通过；预测与真实余额边界清楚 | 18–28 人日 |
| G5 可持续使用验收 | 全流程回归、权限审查、导出恢复、基准测试、使用说明与部署运行手册 | 全部 | 财务与隔离阻断项为零；恢复演练完成，样本报告可复查 | 15–22 人日 |

每阶段对已经交付的入口执行权限、并发和恢复检查；新增文件、导出或周期任务后扩大回归范围，不能把尚未开发的入口标成通过。完整 A01/A02/A17/A19 在 G5 重验。

合计约 **98–150 开发人日**，为基于当前范围的粗估，不是报价或交期承诺，G0 后重估。假设两名熟悉该技术栈的全栈开发者，加兼职业务验收与测试支持，初步约 13–20 周；单人需要更长时间。样本等待、复杂 PDF/OCR、新增机构、公开商业化、自动行情授权及自主衍生品结算不含在估算中。实际团队、投入时间与部署预算尚未确定。

页面框架可在 G1 先展示，但此时只称“界面与基础账本预览”。只有 G5 完成才称首版上线。某机构样本缺失时可继续其他模块，但不能用通用上传功能替代该机构兼容验收。

## 2. G0 必须产出的具体材料

1. **来源登记表：**应用／机构、产品版本、导出入口、文件格式、脱敏样本编号、字段字典、控制合计、支持事件及已知缺口。
2. **金标准样本：**选一个月份及连续交易日，把期初、全部流水、期末、持仓及关联确认单连起来；人工独立确认预期结果，保留计算依据。
3. **底座结论记录：**依据[源码审计 P01–P12](research/open-source-fit.md)，优先验证 Sure 的隔离、撤销、多源消费和基金在途；限定对照工作量，不完整开发两个方案。记录保留／改造的模块、估时依据及最后选择。
4. **可运行最小技术验证：**锁定依赖；两空间、一个原币转账、一个跨币种兑换、一个重复提交、一个队列故障恢复；测试 Decimal 超 28 位中间运算、数据库精度、RLS 及连接复用。这里的“可运行”属于下一开发阶段，当前没有声称已做。
5. **数据与核算决策：**费用默认政策、管理成本、报表范围、历史价格政策、每币种精度及汇率来源策略；默认值与用户偏好分别登记。
6. **版本化接口与页面任务：**冻结首批 API 请求／响应、错误与状态；以原型验证完整导入、查看来源、纠错和贷款确认流程。

G0 不要求提前验证所有机构的全部产品。缺少某一来源样本会阻断其适配和对应阶段验收；核心底座可以用合成数据先验证，但这不能成为“已兼容”的证据。

## 3. 核算政策与预期结果

以下为验收用的管理口径，不是税务算法。数据不完整时返回明确状态，不用零补未知。

| 指标 | 首版定义 |
| --- | --- |
| 净资产 | 同时点、互斥覆盖的资产公允／管理估值合计减负债，使用明确汇率；在途计一次，成本与市值不双计 |
| 自由可安排现金 | 可动用现金减已生效预留和应急金；未来现金流由独立预测计算，避免同一付款既预留又重复扣减 |
| 原币投资金额收益 | 在明确投资范围内：期末价值 − 期初价值 − 期间外部流入 + 期间外部流出；终值、外部流与费用不能重复纳入 |
| 成本与交易盈亏 | 默认移动加权平均管理成本；交易盈亏先按买卖与成本计算，费用／税单列再得到费用后结果；来源机构成本并列核对 |
| XIRR | 求解 Σ CFᵢ/(1+r)^((dᵢ−d₀)/365)=0；从投资者视角投入为负、取回和期末终值为正；r > −1，使用明确搜索域和求解状态 |
| 汇率影响 | 原币收益与折算差异拆开；简单无流量案例采用“原币价格变动按期初汇率 + 期末原币价值乘汇率变动”，交叉项归汇率；有流量时逐段处理并披露方法 |
| 贷款现金流与费用 | 现金流出为本金 + 利息 + 费用；本金减少负债，利息／费用减少净资产；未来应还不算已付款 |

历史费用单列建议由现行“买入费用资本化、卖出减净所得、费用另披露但不重复扣”替代，见domain-model§14及reporting.performance.cost_policy。A10的995份/费用5在当前管理账投资成本包含该费用，不把草案的995成本当现行断言；现金/在途只变一次的验收意图保留。XIRR年化、缺数据/多根和求解状态的原则保留。

## 4. 核心验收案例

全部金额为合成示例，不代表实际产品利率、费率或结算规则。每个案例保存输入、来源、政策版本、预期分录／持仓、报表和运行结果；无需真实账号、姓名。

| 编号 | 输入与动作 | 预期结果 |
| --- | --- | --- |
| A01 家庭隔离 | A/B 空间有相同来源记录号；交叉访问详情、修改、导入、搜索、导出、文件、任务、缓存；连接池连续切换 | 不读不写对方数据，不泄露文件是否存在；缺空间上下文拒绝；运行角色下 RLS 有效 |
| A02 角色撤销 | Viewer 尝试入账；Editor 请求原件下载；Owner 撤销一个正在导出的成员 | 按角色拒绝；失权后的下载和任务结果不可获取；至少保留一个 Owner |
| A03 期初与精度 | 期初现金 10,000；导入高精度基金份额／汇率及超范围数字 | 期初不进入当期收入；合法数值不经 float；超范围明确阻断；逐币种分录平衡 |
| A04 内部转账 | A 出 10,000，B 入 9,998，明确费用 2 | 资产净减少 2，消费费用 2，无收入 9,998 或消费本金 10,000；两侧可溯源 |
| A05 外币兑换 | 支出 7,200 CNY，收入 1,000 USD，无费用，成交汇率 7.2 | 各币种平衡；同汇率下净资产不变；桥接科目不当作额外资产；汇率缺失不按 1 |
| A06 多来源同消费 | 银行、微信、喵喵都记银行卡消费 100；确认其关联 | 一次现金减少 100，一次消费 100，三个证据；不扣微信余额 |
| A07 真重复与真两笔 | 同文件重传、重叠日期、网络重试；另有同日同商户同额两笔，缺稳定号 | 前者不重记，后者不能自动删；两人并发确认同记录仍只有一次经济影响 |
| A08 部分退款 | 原消费 100；银行和微信各显示同一退款 30 | 一次退款，现金净减少 70、净消费 70；退款按实际日期，关联原事项；不冒充新增收入 |
| A09 冲正与依赖 | 期初 100、误记支出 80 改为 60；新批只补证据后撤销；另试图撤销已有卖出的买入 | 更正后余额 40、净支出 60，原分录与冲正不双扣；只补证据的撤销保留既有消费；持仓依赖阻断孤立冲正 |
| A10 QDII 在途 | 计划 1,000，实际扣款 1,000；之后正式确认 995 份、单位成本 1、费用 5 | 计划不扣实账；扣款后在途 1,000；确认后在途清零、投资成本 995、费用 5；不再扣现金 |
| A11 QDII 日期与失败 | 跨假日申购，NAV 日期与发布时间不同；退款后确认单迟到 | 不自动把 T+2 变自然日；只用有证据的状态／日期；冲突待核对，不能退款和持仓双计 |
| A12 管理成本 | 100 份×10，再 100 份×20；卖 50 份×18，卖出费 2 单列 | 均价 15，释放成本 750，剩余 150 份成本 2,250；毛已实现收益 150，费用后 148；现金净增加 898 |
| A13 汇率拆分 | 无现金流，资产由 1,000 USD 变 1,100 USD；汇率 7.0 变 7.2 CNY/USD | 原币收益 100；本位币收益 920，其中价格 700、汇率 220（该约定含交叉项）；合计一致 |
| A14 XIRR | 2025-01-01 投入 1,000，2026-01-01 终值 1,100；再用零投入／缺终值／多根数据 | 完整简单例年化 10%，误差不大于 0.000001 个百分点；异常不出假百分比；多根不能任取一个当唯一解 |
| A15 机构期货权益 | 期初 100,000，入金 10,000，期末机构权益 112,000；同时导入持仓和报告盈亏 | 净资产贡献 112,000；扣净入金变化 2,000，分项未知不标已实现；保证金、名义金额、已含盈亏不再加总 |
| A16 日期与覆盖 | 子例一：期货夜盘自然日与结算交易日不同；子例二：完整现金／股票合成账户从快照转细账 | 子例一分别保留日期，仍按机构权益汇总；子例二切换点先对账，各时点只有一种权威贡献，历史快照可追溯；不要求首版复算期货细账 |
| A17 原子性与并发 | 分录写入后模拟失败、任务重复投递、旧修订重算后完成 | 无半笔事件；重复无新增；outbox 可补投递；旧投影不能覆盖新账本版本 |
| A18 未知格式与证据 | 文件新状态列、缺币种、不符控制合计、预览后改映射；导出含等号开头商户名 | 未知关键语义阻断并定位；旧预览失效；文件不进入公开目录／日志；导出不触发表格公式 |
| A19 备份恢复 | 备份后干净环境恢复，再扫描周期计划、重试任务，导出某空间 | 原账、证据关联、持仓和版本可核对；不夹带其他空间；任务不重记；实测恢复指标 |
| A20 还款拆分 | 月供 4,000，其中本金 2,500、利息 1,500 | 现金 −4,000、负债 −2,500、费用 +1,500；净资产减少 1,500；不把全额当消费 |
| A21 月供自动处理 | 同一期先生成待办、再导入实单；交换顺序、重复任务、离线补跑、手记后再导入 | 预测自动减少；待办阶段实际余额不变；实际只记一次；金额不同进入差异，不自动吞并 |
| A22 多目标与房产 | 初始现金 500,000，预留 200,000；随后购房价 1,000,000、实际首付 300,000、贷款 700,000，无费用 | 预留时资产 500,000、自由现金 300,000；成交后现金 200,000、房产 1,000,000、债务 700,000，净资产仍 500,000；多个方案不叠加 |
| A23 港美股结算 | 先有成交、后有资金交收；分红 100 USD、预扣税 10、到账 90 | 成交／交收各自有事实；证券与应收应付、已交收现金不双计；分红总额 100、税 10、现金 90；结算日期依实际记录 |
| A24 红利再投与拆分 | 同一分红既有现金确认又再投资；已持 100 份按 1:2 拆分，无其他变动 | 分红与再投关联，只计一次收益；份额变 200、总成本不变、单位成本减半；不把拆分当外部投入 |
| A25 期权机构范围 | 股权／商品等实际涉及期权的机构结算样本，含乘数、权利金／保证金或到期信息 | 按机构定义展示和对账，保留来源；已在权益中的期权价值不再加总；缺产品验证明确不支持分析，不按通用股票公式复算 |
| A26 贷款计划计算 | 本金 2,100,000，固定年利率 3%，360 期，月利率年率/12；另测 0 利率、等额本金、短月还款日及提前还款 | 简化等额本息月供 8,853.68，首期利息 5,250、本金 3,603.68；累计本金回收等于原本金，末期处理舍入；实际计划不同则保留差异并按机构计划执行 |
| A27 新资金与旧快照 | 银行 50,000、期货旧快照 100,000；转出 10,000，随后到账确认，再来明确含此入金的新权益 111,500 | 未到账为银行 40,000＋在途 10,000＋旧权益 100,000；到账后在途归零、期货暂估 110,000；新快照后银行＋期货 151,500，调整不重加；快照间行情未覆盖须标暂估 |
| A28 还款拆分晚到 | 银行先证实扣 4,000，无拆分；后来贷款单显示本金 2,500、利息 1,500，重复导入两次 | 初期现金减少一次并建待分配清算，净资产／负债／费用不完整；后续清算归零，贷款减 2,500、费用 1,500，现金不再动 |
| A29 多阶段与请求身份 | 基金先扣后确认、部分确认／退款、多源补同阶段证据；相同请求幂等键更换内容重试 | 生命周期多阶段追加，旧扣款不可变；每阶段一次生效；同键不同内容冲突，相同内容返回原结果；不同调用者仍由来源约束防止重复经济事实 |

A14 的多根反例可用每隔 365 天的现金流 −100、+230、−132，对应年率 10% 和 20%；系统必须呈现非唯一状态。独立基准不能调用同一套待测业务函数生成期望值。

G0 核验只是验证底座能表达关键事实，不能替代以后全部案例的真实样本回归。首版期货期权的 A15/A16/A25 验收是映射、汇总和对账，不包含自主算保证金、平今平昨或行权现金交割。

## 5. 页面与操作验收

- 在约 1440px 桌面完成“上传 → 映射 → 看疑似重复 → 确认 → 查看余额变化 → 查看原始行 → 对账 → 冲正”；1024px 不丢失确认、错误和关键金额。
- 顶部持续显示当前空间；切空间时清理旧数据，加载中不闪现上一空间金额。
- 实际、机构正式、估算、预测、待确认和数据缺失有文字标记，不能只靠颜色；键盘可完成核心表单。
- 确认页面写明改变哪些账户、金额和份额。只补充证据时说明实际金额不变；冲正前显示依赖。
- 目标比较可追溯使用的现金、预留、收入与费用假设；证券市值不能直接当作当日可用资金。
- 错误可以回到具体行／字段，网络超时后能查询原提交结果；不迫使用户反复上传猜测是否成功。

## 6. 测试组织与上线定义

财务计算用独立算例和属性不变量验证；数据库约束、RLS、锁和并发在真实 PostgreSQL 测试；解析器按格式版本保留合成与授权脱敏样本；完整网页流程由浏览器测试覆盖。每次变更按影响范围重跑，不为文档或样式小改重复整个金融测试集。

G5 必须具备：

- 首批五个来源每个都有支持清单、样本版本、预期与结果；支付宝、微信、银行及具体港美券商按已经取得的格式分别标明能力。港美证券的通用结构化导入必须可用，不能因此声称所有券商原生支持。
- 金额、隔离、重复提交、冲正、快照覆盖及恢复案例没有未解决的阻断缺陷。
- 已记录测试硬件和 PRD 性能规模，确认慢任务进度、取消和失败处理；不能只验证空数据库。
- 恢复演练报告、版本锁、部署配置说明、密钥与访问管理、管理员操作手册、用户导入指南。
