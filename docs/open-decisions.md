# Wealth 决策登记与样本准备

更新：2026-09-16。本文把用户已经确认的要求、当前设计默认值、仍需外部输入的事项分开。未回答的偏好不当作同意；不影响的工作可以继续。

## 1. 已确认的产品要求

| 事项 | 当前结论 |
| --- | --- |
| 首版用户 | 多个相互独立的用户或家庭 |
| 首版入口 | 中文电脑网页端 |
| 投资范围 | 境内、港股、美股及外币 |
| 首批具名来源 | 喵喵记账、广发期货、银河期货、广发基金、易方达基金 |
| 原始导入需求 | 现有记账软件及支付宝、微信账单；银行和投资机构数据统一管理 |
| 主要场景 | 多账户资产、投资与结算、定投、预计／实际收益、大额支出、月供等自动计入 |
| 特别基金场景 | 红利低波和用户称为 T+2 的 QDII；具体产品未识别 |

## 2. 当前设计默认值

这些默认值用于形成可开发方案，尚不是用户确认的运营安排。变更时先判断是否影响已有账本或权限，再更新相关文档。

| 决策 | 默认设计 | 改动影响 |
| --- | --- | --- |
| 空间与身份 | 个人／家庭都用账簿空间；同一用户可以加入多个空间 | 认证与对象归属，需早定 |
| 角色 | Owner 管成员及完整导出，Editor 编辑／导入／核对，Viewer 页面只读；原件下载仅 Owner | 页面、API、文件与任务统一授权 |
| 家庭内可见性 | 同空间按角色共享；私人账户留在私人空间 | 若要求单账户隐藏，要另建权限维度 |
| 交付方式 | 暂按邀请制集中托管设计，不启用收费或公开注册 | 部署、身份、支持和数据保留政策 |
| 首批币种 | CNY、HKD、USD；数据模型可扩展其他币种 | 其他币种需精度、汇率及样本验证 |
| 本位币 | 默认 CNY，建账前可选；有正式账后保留原币事实，其他展示币种走报表换算 | 更换会计本位币需迁移，不静默重写历史 |
| 技术路线 | React + Django/DRF + PostgreSQL 模块化单体；G0 对照 Sure，证据可推翻选择 | 未开始应用实现前修改成本最低 |
| 管理成本与费用 | 移动加权平均；拟默认费用单列，资本化需明确政策与版本 | 盈亏和机构成本比较；不等同税务成本 |
| 自动月供 | 预测扣减、到期待核对；确认实单后记实际账 | 没有银行支付授权或真实代扣功能 |
| 首版期货期权 | 机构结算单导入、权益与持仓展示、对账 | 自建逐笔结算引擎是后续增量，不隐含在首版 |
| 行情基线 | 机构文件、手工或标准文件录入价格／汇率，保留时点 | 自动报价要另定覆盖、授权、价格与延迟 |

## 3. 仍需补齐的输入

| 编号 | 需要的信息 | 用于什么决定 | 何时必须具备 |
| --- | --- | --- | --- |
| D01 | 喵喵记账的准确产品名称、版本、导出入口和原始格式 | 适配字段、账户转账、历史分类迁移 | G2 该来源开发前 |
| D02 | 首批港美股券商及实际交易市场；境内股票券商如需原生适配也需列明 | 原生导入格式、成交／交收、股息税费、账户币种 | G3 对应适配前；通用格式可先做 |
| D03 | 广发／易方达具体基金代码、份额类别、人民币／外币类别和购买渠道 | 唯一产品身份、确认规则、净值时间 | G3 基金验收前 |
| D04 | 广发／银河连续结算单和实际涉及的期货、期权合约 | 机构字段定义、权益覆盖、夜盘归属、费用对账 | G3 结算适配前 |
| D05 | 同一笔基金交易的申请、扣款、确认、赎回到账或退款链条 | 验证在途和重复归并 | G3 基金验收前 |
| D06 | 首个银行样本、支付宝／微信重叠样本，与喵喵同交易案例 | 支付渠道识别、同消费归并、退款和转账 | G2 对账验收前 |
| D07 | 期初启用日、可取得的历史范围、持仓成本是否完整 | 期初迁移和收益的可计算区间 | 首次真实建账前 |
| D08 | 新贷款测算还是接续既有贷款；如接续，剩余本金及机构应还计划 | 不同还款方式、实际拆分和调整 | G4 真实贷款验收前 |
| D09 | 统一托管或自托管、预计首批家庭数、预算、开发参与人员 | 容量基准、部署、工期和维护分工 | G0 估算／G5 部署前逐步落实 |
| D10 | 是否接受开源 fork 的许可证义务；是否存在闭源商业化要求 | Sure 二次开发路线与代码复用方式 | 复制或修改对应开源代码前 |
| D11 | 原始文件保留时长、空间删除流程、支持访问和恢复责任人 | 文件、备份、权限与运维 | G5 使用真实数据前 |

以上输入缺失不阻止本轮需求与架构文档完成；阻止的是对应适配、运行或上线承诺。没有样本时，不把“支持 CSV”写成“已支持该机构”。

## 4. 最小样本包

优先取得小而完整的链条，不需要一开始提供全部历史。保留原文件类型、表头、编码、列顺序和工作表，另附该文件在软件中的导出入口说明。

| 来源 | 最小建议内容 |
| --- | --- |
| 喵喵记账 | 一个短期间的账户、分类、消费、转账、退款；尽量含一笔已在基金或银行出现的投资扣款 |
| 支付宝／微信／银行 | 同一笔银行卡消费及退款的对应记录；两笔同额真交易；钱包充值或转账 |
| 广发基金／易方达基金 | 普通基金与目标 QDII 的代码、份额类别；一笔从扣款到确认的完整链条，适用时含赎回或退款 |
| 广发期货／银河期货 | 连续数个交易日的结算单，含期初、期末、出入金、手续费和实际持仓；有夜盘或期权时保留相应记录 |
| 港美券商 | 成交、现金流水、期末持仓／账户值、换汇、股息及预扣税；重复导出或重叠期间一份 |
| 贷款 | 合同关键计算条件或机构还款计划、一次实际扣款及本金／利息拆分；无需完整合同个人页 |

姓名、证件号、住址、电话、完整账号和登录信息可去除；将账户、订单和交易号一致替换为匿名编号，跨文件保持同一映射。不要删除区分两笔交易的唯一性，也不要随意改金额破坏期初＋变动＝期末关系。若金额也需脱敏，生成整套算术一致的替代样本，并注明它不是机构原始对账结果。

不需要提供密码、验证码、支付授权或可用登录凭证。样本保存在私有验证位置，不进入公开仓库、日志或默认外部 AI 服务。仅有 PDF 时先验证文本结构；扫描件 OCR 不在首版默认承诺内，不能在看过格式前估成普通表格适配。

## 5. 本轮状态与下一步

本轮完成开发前文件，应用尚未开发。下一步 G0 可先用合成样本验证隔离、精度、事务和重复导入；真实格式到齐后补来源验证并更新工期。没有必要在等待某个基金代码时暂停所有独立工作，但对应基金不能先标为兼容。
