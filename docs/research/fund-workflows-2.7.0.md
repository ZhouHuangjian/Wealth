# 基金交易与定投交互改造（2.7.0）

研究日期：2026-09-30。参考 [real-time-fund](https://github.com/hzm0321/real-time-fund) 的 `373ee71409256e2208f88bb9a83c99a9320f20b1` 版本，重点阅读交易、定投、持仓操作及待确认队列。参考项目采用 AGPL-3.0；本项目独立实现流程，没有复制其代码或引入其依赖。

借鉴金额优先的买入、份额优先的卖出、持仓就近操作、按计划生成期次、正式净值到齐后处理待确认的交互。继续沿用本项目的多空间权限、数据库事务、Decimal、不可变分录与操作来源；不采用浏览器本地存储作为金融事实来源，也不以缺失价格的零值代替真实数据。

## 日常操作

- 普通支出默认带出最近使用的账户、分类及今日日期，均可直接修改。备注和凭证可空，保存后可撤销；编辑已有流水通过关联更正保留原记录。
- 持仓买入先填金额并选择当前已知状态：申请、已扣款、机构已确认。申请不改变资金或持仓；已扣款进入申购在途；份额确认后在途转入持仓。
- 每只基金在每个持仓账户可记住扣款账户、费用和份额推算选择。默认来源及费用状态可见；费用、截点和备注按需展开。
- 有机构闲置现金时可选择该机构账户；也可选择银行卡等同币种明细账户。未维护资金来源时明确选择“账外资金”，以追加本金记账，不扣本账簿账户、不记为收入。之后可补充实际扣款账户，不重复记份额或资产。
- 转换按已知的实际转出份额、净值和费用记录，转出、内部到账和目标申购在同一事务中完成，目标份额可稍后确认。分红、交易记录和定投从持仓操作菜单进入。

## 定投与异常

建立计划不代表扣款成功。开启“按计划自动补录”才授权按规则推算发生的扣款；原有计划不会在升级时自动开启。费用未知时仍可记录扣款，但不推算份额；费用支持已确认零费用、固定费用和申购费率。可排除失败日期和暂停区间。

推算使用开放日历、截止时间、预计确认日、对应交易日的正式净值及产品份额精度；不使用盘中估值确认份额。资料不足时保留待核实，不伪造机构确认；自动结果始终带推算来源。单笔买入也可明确开启正式净值公布后推算份额。机构确认到来后，可核实并更正推算份额；存在后续依赖时需先处理相关交易，不能抹去历史。

“收支账本 → 投资交易”和“待办 → 基金待核实”集中展示申请、待确认和推算待核实。已有实际确认会关联到原扣款，避免再次确认。相同日期、相同金额允许是两笔交易；重复请求使用原幂等标识去重。

## 分析范围

账户显示开始记录日期及历史完整程度。余额记录用于资产总额和余额变化，不单凭余额上涨推导投资收益；历史未核实或不完整时不提供无依据的完整收益及年化。底层保留金额、份额和净值精度，页面金额维持两位显示。

依照 [W3C 防错说明](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)，普通保存优先撤销和校验，覆盖或撤销有账务影响的记录给出具体说明。[Stripe 幂等机制](https://docs.stripe.com/api/idempotent_requests)用于设计安全重试；原有 [PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html)与[精确数值类型](https://www.postgresql.org/docs/current/datatype-numeric.html)继续承担核心一致性。

当前限制：没有银行或基金机构交易授权连接，不实际下单；公开净值与交易日资料不能证明机构已经扣款或确认。卖出、转换和分红仍按实际已知事实录入，尚未新增赎回申请的完整受理生命周期。自动估算与正式机构记录不会混为一谈。
