# ADR 0001：V2 实施基线与单一账本

- 日期：2026-09-25
- 状态：本次实现采用；完整首版验收仍受 G0—G5 约束
- 依据：[V2 需求原文](../requirements-v2.md)、[现有开源调研](../research/open-source-fit.md)

## 决议

按照用户此次“完成项目开发”的明确指令开始实现。上传 V2 中“本轮只写文档”描述的是该稿形成时的范围，不覆盖本次开发授权。`requirements-v2.md` 原样保留，不篡改其内容来制造验收通过记录。

采用 React + TypeScript + Vite、Django 5.2 + DRF、PostgreSQL 18 的模块化单体。生产式本地容器以 Python 3.13 运行；当前工作机先以 Python 3.12 验证，不能把两者混称同一环境已通过。依赖精确版本以实际锁文件和测试结果为准。

前端输出静态资源，由 Django/WhiteNoise 同源提供。Celery 使用同一后端镜像，RabbitMQ 仅在内部网络提供消息队列。金额、份额、状态、收益和权限的最终判断在后端；前端不维护第二套可写余额。

数据库事务、任务重试和业务幂等各有职责。账务事实提交与 outbox 同事务；消息可以重复，消费者必须以数据库约束和修订版本保证结果唯一。计划到期只产生待办，不制造金融机构已扣款、已确认或已成交的事实。

## 自建与 Sure 的边界

旧调研记录了 Sure 的家庭权限模型与 Wealthfolio 的单账本限制。当前选用自建，原因是 V2 所需的多源经济事项归并、按币种平衡、基金在途和确认、机构快照互斥贡献、跨空间关系约束需要一致的领域模型。不得把不同开源项目各自可修改余额的模块简单拼接。

这项实施决策不是“Sure 已在金标准下运行失败”的证据：尚无相同真实样本下的完整 Sure 可运行对照结果。V2 G0 的该项验证仍在状态表中保留。若后续对照证据足以改变路线，应修改 ADR 和迁移计划，而非隐藏双账本。未复制 AGPL 项目源码；未来引入第三方实现须记录来源和许可证。

## 发布约束

可运行应用、合成数据测试通过、真实机构来源兼容、完整 P0 发布是不同结论。五个具名来源未取得真实脱敏样本前，必须标记“待样本验证”。RPO、RTO、容量与性能以演练或测量记录为依据。
