# Wealth 产品需求与首版边界

版本：0.1 · 更新：2026-09-16 · 状态：开发前设计基线，尚未实现。

## 1. 产品目标

为多个独立用户或家庭建立可核对的资产总账，贯通日常收支、跨机构投资、定投、大额支出与每月还款。第一版为中文电脑网页端。

系统必须回答：钱在哪里；资产负债和可动用资金有多少；收入结余、投资及汇率分别造成多少变化；未来的大额付款和还款会不会造成缺口。

## 2. 已确认需求与设计默认值

| 项目 | 已确认内容 |
| --- | --- |
| 使用对象 | 从第一版就支持多个独立用户或家庭，彼此隔离 |
| 界面 | 电脑网页端优先，中文 |
| 市场 | 境内、港股、美股及外币均纳入首版 |
| 资产 | 多银行、现金、基金、股票、期货、期权 |
| 现有来源 | 喵喵记账、广发期货、银河期货、广发基金、易方达基金 |
| 其他导入 | 支付宝、微信及银行／券商账单 |
| 基金场景 | 红利低波、QDII、定投、预估与实际收益；用户提及 T+2 |
| 规划 | 买房及其他大额支出，月供等周期性现金流自动计入 |

设计默认值：个人空间和家庭空间都称为账簿空间；一个用户可加入多个空间；空间默认本位币为 CNY，首版支持 CNY/HKD/USD；首版以邀请方式加入，暂不做公开注册和收费。这些是实现建议，不是用户已经确认的商业安排。

“红利低波”是策略标签，不是唯一产品标识；实际适配必须取得基金代码、份额类别和销售渠道。港美股具体券商、喵喵记账版本及所有文件格式仍待样本核验。

## 3. 首版的交付定义

首版指通过 G0–G5 验收的可持续使用版本，不是只展示模拟数据的界面。开发过程中可以先交付可点击页面，但页面预览不能替代首版验收。

| 层次 | 首版必须完成 | 后续增强 |
| --- | --- | --- |
| 身份与权限 | 独立空间、成员角色、隔离、审计 | 精细到单账户的家庭内共享规则、公开注册与订阅 |
| 基础账本 | 多币种现金／负债、期初余额、转账、退款、对账 | 企业法定会计、完整税务报表 |
| 导入 | 原始文件、预览、映射、去重、关联、确认、撤销／冲正；首批来源适配 | 更多机构、OCR、经授权的自动同步 |
| 基金股票 | 实际交易、持仓、分红、费用、拆分、成本及收益；基金在途与确认 | 复杂重组、配股等专用流程、税务成本优化 |
| 港美与外币 | 市场／币种身份、原币与本位币展示、换汇、股息及预扣税事实、通用文件映射 | 按未知券商批量开发专用连接器 |
| 期货期权 | 广发／银河结算数据、权益、保证金、可用资金、持仓及机构报告盈亏汇总与对账 | 全市场逐笔结算复算、组合保证金、自建风险引擎 |
| 定投 | 计划、实际扣款与确认、失败／跳过、收益统计、情景测算 | 自动下单、策略交易 |
| 目标与还款 | 大额支出、多阶段付款、贷款计划、预计现金流、到期待核对、实账匹配 | 组合贷款优化、复杂浮息重定价、自动资金调拨 |

首版“支持期货期权”必须在界面注明“机构结算口径”。不把机构数据导入称为自主结算复算；未适配字段和未验证产品明确显示覆盖不足。

## 4. 功能需求

### FR-01 账簿空间与成员

- 空间是数据隔离边界。账户、文件、交易、投资、计划、任务和导出均属于一个空间。
- Owner 管理成员、权限、空间设置、导出和归档；Editor 记账、导入、核对和管理计划；Viewer 只读页面。原始文件下载和完整导出默认仅 Owner 可执行。
- 一个用户可以拥有私人空间，同时加入家庭空间；切换空间需明确显示名称，绝不在后台自动合并两者。
- 初版同一家庭空间内账务对获准成员可见。需要隐藏的私人账户应放在私人空间；不得以“家庭功能”隐含授权查看私人数据。
- 平台运维角色与家庭 Owner 分开；平台管理界面默认不展示金融明细。必要支持访问要有独立授权和审计。

### FR-02 账户与期初初始化

- 按机构、所有人、账户类型、币种建立账户。多币种券商账户含原币子余额，但总览避免重复汇总父子账户。
- 支持银行、现金、支付钱包、基金渠道、证券账户、期货账户、信用卡、贷款及房产资产。
- 用户选择启用日期，录入余额、负债、份额和已知成本；原有资金进入期初权益，不计为工资或投资收入。
- 每个账户展示数据截止时间、数据来源、最近核对时间、完整性状态。
- 未知成本和历史缺失不能填写为零。允许从启用日向前补账，并重算受影响区间。

### FR-03 账单导入与规范化

- 流程：选择空间与来源 → 上传 → 格式识别 → 账户／字段映射 → 预览 → 处理重复、退款和转账 → 确认 → 对账。
- 同源重复和跨来源同一事项分别处理：同源重复不再记账；跨来源记录作为同一经济事项的证据。
- 喵喵记账承担历史分类和补充来源；金融机构记录优先解释真实资金及成交，但不得无痕覆盖用户已有分类或修订。
- 支持错误行导出、批次进度、可重试、解析器版本、原始行定位；未知格式进入映射／待处理状态。
- 不将“已能上传 CSV”标成某机构已适配。具体机构需通过脱敏样本和对应结算结果验收。

### FR-04 收支、转账和退款

- 消费与收入支持拆分分类、标签、备注、归属成员及附件。
- 银行卡经微信付款只形成一笔消费；钱包充值、证券入金和家庭空间内转账不增加收入或消费。
- 退款关联原消费，允许部分退款和跨月退款；报表可看发生期与原消费关联，不修改原记录时间。
- 信用卡消费计费用并增加负债；还款减少现金和负债，费用只单列当期利息／手续费。

### FR-05 多币种与跨市场

- 同时保存原始金额／币种和折算依据。不同币种禁止直接相加；本位币仅用于统一展示和报告。
- 汇率需要来源、报价方向、适用日、取得时间；缺失时显示原币与未折算项，不默认按 1:1 或自动用今天汇率重写历史。
- 区分交易实际换汇汇率、历史估值汇率和规划假设汇率；汇兑损益不冒充标的涨跌。
- 保存市场交易日、交收日、来源时区和 UTC 事件时间。日期只有“日”的账单不伪造精确时刻。
- 证券成交与资金交收可以分离：成交建立持仓及交收应收／应付，实际交收清算；已交收现金、可交易和可提取金额分别表达，不重复扣款。
- 相同代码不同市场、同一基金不同份额／币种不得合并为同一资产。

### FR-06 基金、股票与投资收益

- 支持买入／申购、卖出／赎回、现金分红、红利再投、拆分、费用、股息预扣税、持仓转入转出。
- 份额、价格、费用和成交净额均可追溯至机构证据。成本默认采用管理口径移动加权平均，保留真实批次和机构报告成本供核对；不把该口径称为税务成本。
- QDII 单独记录申请、扣款、交易归属、确认、净值有效日／发布时间与资金到账；“T+2”不是全体产品的统一确认或到账规则。
- 申购扣款后先进入在途；确认后转持仓，失败时退款。赎回先形成应收／在途，到账后转现金，避免空窗或双计。
- 面板分别展示期间净投入、期末价值、已实现盈亏、未实现盈亏、分红、费用和汇率影响。
- 资金加权年化收益采用 XIRR 类口径，明确组合范围与期末估值；内部转账不算整个组合外部现金流。历史或估值不足、无解或多解时不给唯一精确收益率。
- 预测收益、估算净值、正式净值、已实现收益必须有清晰标签。正式净值也要标明其有效日期，不用发布日期冒充收益发生日。

### FR-07 期货与期权

- 首版以广发、银河正式结算单／导出报告为核心事实源，支持结算日权益、出入金、报告盈亏、手续费、保证金及可用资金的字段映射和差额检查。
- 账户权益、保证金、可用资金分别展示，保证金是权益中的占用部分；合约名义价值不直接加入净资产。
- 同一账户同一日期区间，只选机构权益快照或细账汇总作为总览贡献，不能把两种口径相加。
- 新出入金早于新快照时，分别表达转账在途或已证实资金的滚动调整；新快照包含后移除调整。未覆盖的新盈亏明确标为暂估，覆盖不明时不发布完整净资产。
- 支持保留开平、方向、合约乘数、到期、期权类型及行权价等明细；缺失关键字段时限制相应分析。
- 夜盘自然日与交易日分别保存。逐笔复算、平今平昨、现金／实物交割、指派／行权、保证金模型按具体产品在后续阶段逐项验收。

### FR-08 定投

- 计划包含目标资产、资金账户、频率、计划金额／币种、开始与结束日期，以及暂停／跳过规则。
- 每期是可追踪的计划项，可关联扣款、确认份额和退款；计划存在不等于实际成交。
- 统计计划投入、实际扣款、已确认投入、漏投／失败、份额、收益，QDII 未确认订单不能冒充已完成。
- 未来测算允许设置收益假设、费用和投入频率；实际表现独立计算，不将预测写入账本。

### FR-09 大额支出规划

- 支持买房、购车、装修及自定义目标；记录预算、币种、目标日期、优先级、付款节点和资金来源。
- 买房拆分定金、首付、税费、装修和贷款。各节点避免与已含税的总预算重复；所有预留仍是资产，不提前改实际余额。
- 多目标、应急金、定投和还款共用资金池，显示已分配、可再安排和缺口；同一笔资金不得重复承诺。
- 预测按月展示，近期按付款日列出；现金流按实际到账可能性区分“已确认／合同计划／可调整假设”，不能把证券市值等同即时可用现金。
- 首版提供方案复制比较：调整金额、日期、首付、定投或贷款期限；所有方案互斥模拟，不叠加扣款。用户选择启用方案后才占用规划资金。
- 购房实际完成后，由确认事件增加房产资产与贷款负债；税费的成本化／费用化采用显式管理政策，不与首付重复扣减净资产。

### FR-10 贷款与周期还款

- 新建或接续现有贷款，记录剩余本金、币种、期数、还款方式、合同利率、扣款账户、还款日及首期日期。既有贷款可直接导入机构计划，不强制补齐原始发放历史。
- 支持固定利率等额本息、等额本金及自定义逐期计划。信用卡账单、浮息或混合贷款优先导入实际应还计划，未配置利率规则不伪算固定月供。
- 自动扣除的首版含义：计划现金流自动扣减，到期生成待核对记录；默认不改实际余额。人工确认或匹配实际账单后记账。
- 每期记录稳定编号；任务重试、离线补跑、账单先到、手动先记均只形成一次实际还款。金额不符进入差异处理。
- 整笔还款是现金流出；其中本金减少负债，利息和费用进入费用。禁止将整笔月供作为消费后又额外冲减贷款。
- 只有真实扣款、缺贷款拆分时，现金先通过待分配清算入账，负债和费用待证据补齐后重分类，不能猜拆分或再扣一次；期间净资产显示不完整。
- 支持未来期暂停／延期／更新、机构新计划替换未发生部分。提前还款事实可记录本金和费用，未来计划按新机构计划更新；最优提前还款策略不属首版。
- 29–31 日在短月的处理可配置为月末，默认按合同／导入计划；周末与节假日不擅自假定银行扣款规则。
- 后台服务持续运行时无需打开网页；系统停机后补生成到期事项，不将补跑当成真实支付成功。

### FR-11 对账、报表与可追溯

- 现金余额、持仓份额、贷款本金和期货账户权益各有对账对象，差额不可通过无说明的“自动调平”隐藏。
- 对账保留截止日期、机构值、系统值、差额、处理人与证据；核对通过的历史修订会使相关核对状态失效。
- 总览分开显示净资产、可用现金、生活费用、投资收益、全部现金流出及规划后的可安排资金。
- 任何关键指标可追溯至范围、日期、汇率、估值、交易和原始记录；缺失或过期数据按字段标识。
- 导出规范化数据和配置；支持备份恢复。批量撤销只影响该批产生的变化，已被其他证据支持的事项要先检查依赖。

## 5. 电脑端页面结构

全局顶部：空间切换、本位币、统计日期、数据状态与待办数。默认宽度 1440px 设计，1024px 可完整操作；窄屏只保证基本可读，不单独开发原生 App。

| 页面 | 主内容 | 必须可执行的操作 |
| --- | --- | --- |
| 总览 | 净资产趋势、币种与机构分布、现金与预留、数据缺口 | 切范围／日期；追溯变化 |
| 账户 | 账户树、原币余额、机构权益、所有人、截止日 | 开户档案、期初录入、归档、核对 |
| 账单中心 | 批次列表、原始与规范化行对照、异常和重复 | 上传、映射、关联、确认、冲正 |
| 持仓与收益 | 持仓、成本、价格时间、盈亏、基金在途；期货独立视图 | 录交易、更新估值、查看来源和核算口径 |
| 定投 | 计划与每期执行、确认进度、历史收益和预测 | 新增、暂停、跳过、关联实单 |
| 目标与还款 | 多目标、付款节点、现金流方案、每期本金利息 | 启用方案、调整预留、管理还款、确认到账 |
| 对账与待办 | 差额、待确认、缺净值、缺汇率、逾期待处理 | 逐项修正并记录理由 |
| 设置 | 成员、角色、本位币、隐私、导出、备份 | 权限管理、数据迁移、恢复 |

## 6. 非功能验收目标

这些是待测试的目标，不是当前已达到的能力。

- 隔离：跨空间的列表、详情、下载、导出、搜索、后台任务、缓存和汇总都不可读取或修改其他空间数据。
- 正确性：实际分录平衡；金额、数量和费用保留来源精度；所有金额计算用十进制，收益数值求解单独规定误差。
- 可恢复：首版目标为每日加密备份、恢复点不超过 24 小时、恢复操作目标不超过 4 小时，必须做恢复演练后才能对外承诺。
- 性能基准：暂以 100 个空间、每空间 10 万条原始记录、20 个并发会话为测试规模；这不是业务增长预测。需记录测试硬件。常用列表 p95 < 1 秒；缓存就绪的总览 p95 < 2 秒；1 万行结构化文件解析预览目标 < 60 秒，耗时任务显示进度和取消状态。
- 数据导入错误必须可定位；日志不记录原始账单、完整账号、身份证、口令。
- 上传、文件和数据库独立备份；恢复后后台任务仍能幂等补跑。

## 7. 明确边界

本系统管理、核算和规划资金。首版没有银行代扣、转账、基金申购、证券下单和自动交易能力。也不将未授权行情抓取、税务申报、投资建议或企业会计作为默认功能。

一期行情基线为机构账单、确认单、手工／标准文件导入的价格和汇率；可接入经核验的数据提供方，但自动行情的覆盖、授权、费用和延迟尚未确定。没有新行情时保留日期并显示缺口，不伪装实时。
