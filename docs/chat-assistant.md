# 聊天助手：Wealth 登录，Mac 生成草稿

> 2.14.7 已增加完整历史存档与统一模型中心。「会话动态」支持历史翻页、解析文字、逐条意图、候选回复及档案记忆摘要，并从网页请求刷新、识别、分析和生成草稿。最新功能和同步范围请以[远程使用说明](../clients/xiangzhi/docs/remote-contact-settings.md)为准；下面的首次连接和历史协议说明保留用于旧版接入。

聊天助手复用拾财已有账号和登录会话。管理员在聊天管理中为具体账号启用功能；管理员自己的聊天也属于个人账号，不需要创建财务空间。会话草稿按个人账号隔离，不沿用家庭账簿的成员共享或管理员代管权限。

## 首次连接

1. 登录拾财，进入独立管理台的聊天管理，为需要使用的账号启用聊天助手。
2. 该账号进入“聊天助手 → 我的设备”，添加设备，例如“我的 Mac”。管理员直接使用管理工作台固定的“我的聊天”标签，无需进入代管空间。连接配置可复制或下载，也可随后从设备卡的“查看配置”再次获取。
3. 在 Mac 相知工作台的设置中粘贴连接配置并保存；保存后会验证一次 Wealth 连接，也可随时点击“验证连接”。配置形如 `{"uploadUrl":"https://你的服务器/api/v1/chat/ingest","token":"设备令牌"}`；不要把真实令牌发给他人或提交 Git。
4. 在 Mac 生成一批候选回复，先手动同步，回到网页刷新核对。需要持续上传时，再在 Mac 开启自动同步。

保存连接只保存配置，不会上传历史聊天或草稿。更换、清除连接时自动同步暂停，需核对后重新开启。清除连接不会自动恢复环境变量里的旧凭据；确有需要时使用“恢复环境配置”。连接验证只发送设备凭据和空请求，更新最近验证时间，不上传聊天或草稿；“已验证连接”不表示 Mac 实时在线。普通同步服务不支持 Wealth 验证端点时，仍以实际草稿同步确认结果为准。环境变量 `DRAFT_SYNC_URL` 和 `DRAFT_SYNC_TOKEN` 仍可用于旧客户端配置。

绑定配置保存在 Mac 当前数据实例的私有目录中，令牌不进入工作台状态接口、聊天导出或浏览器存储。云端保留鉴权摘要及按账号、设备分开加密的凭据，仅本人可重新获取配置；列表不返回令牌。2.13.0 创建的旧设备只有摘要，无法还原原配置，可点击“重新生成配置”：旧配置会失效，设备和草稿保留，随后需在 Mac 粘贴新配置。新配置可反复查看，不会因查看而失效。设备令牌与网站密码、服务器 SSH 密码互不替代。

## 当前能力

- 查看自己已同步的联系人草稿，按联系人查找，加载历史批次，复制候选回复和管理回收站。
- 查看本人设备及最后上传时间，撤销或永久删除设备；管理员查看账号启用状态和设备数量。
- 云端接收与 Mac 现有草稿协议兼容：每批最多三条候选，按设备和批次去重；同一批次不同内容拒绝覆盖。
- 关闭账号聊天权限、停用账号或撤销设备后，新上传立即被拒绝。管理员没有读取其他账号草稿正文的接口。

网页复制草稿不等于微信发送。网页可管理绑定 Mac 的模型、联系人、功能开关、档案与记忆，并请求 Mac 手动重新生成。微信采集与模型调用仍在 Mac 执行，云端保存已上传草稿和最近消息快照，不包含完整聊天历史。Mac 离线时仍可查看已同步内容，新结果须待 Mac 恢复运行后生成并上传。实际使用前核对最新来信。

每个人应连接自己的 Mac 数据实例。不要把含有甲用户聊天的实例改绑给乙用户后继续上传；设备归属由创建时的登录账号决定，上传正文不能更改归属。

## 网页远程管理 Mac

进入“我的设备”，选择设备的“远程管理”。Mac 须已导入该设备的连接配置、启动相知，并开启本地“允许网页远程管理”。Mac 主动向已有服务器连接，不需要公网访问 Mac 或开放新的入站端口。

可调整草稿模型、模型名称、回复延迟、冷却间隔、每日上限、安静时段，以及自动草稿和草稿同步开关。接口地址、API 密钥、设备凭据、微信密钥和系统命令不在远程配置范围内；需要使用的模型应先在本地完成配置。网页的自动处理始终为草稿模式。

联系人搜索由当前 Mac 执行，网页只显示本次搜索的有限结果。选中联系人添加后，默认暂停采集与自动草稿；在该联系人设置中分别开启。已有联系人可修改名称、备注和这两个开关。开采集后先补齐上下文，之后的新来信才按已有规则触发自动草稿。

网页提交后先显示等待执行，收到 Mac 回执才显示完成或失败。Mac 暂时离线时操作会等待，超过有效期会标记过期，需要重新提交。最近连接时间不能保证 Mac 此刻在线；页面同时显示快照更新时间。关闭本地远程管理后停止接收新操作。

云端保存配置快照、已接入联系人的名称与标识、显式搜索的结果及操作状态。2.14.7 另用有序批次同步已接入联系人的完整已读消息及解析、意图，网页按页查看。近况快照仍是有界预览，草稿和档案记忆通过原有机制同步；个人习惯档案、原始媒体和模型凭据保留在 Mac。各账号只能管理自己的设备，管理员代管财务空间不授予他人聊天设备权限。撤销或删除设备使旧凭据失效，重新生成配置会使旧的待执行操作失效。

## 回收站与永久删除

回复草稿可先移入回收站，之后恢复或永久删除。逻辑删除会保留内容及批次记录，重复上传不会使回收站内的草稿自动恢复。2.13.0 旧版删除时已经清空正文的记录不能恢复，页面会明确标记并提供永久删除。

永久删除草稿会清除该批次的云端数据记录，不可恢复；Mac 原始聊天和本地草稿保留。之后若从 Mac 再次同步该批次（包括仍在途的上传），可能在云端重新建立记录。

撤销设备只使凭据失效，已同步草稿仍可查看。永久删除设备会移除设备及它的全部云端草稿（包括回收站）、远程操作记录和配置快照，页面显示当前关联数量并确认影响范围。此后旧凭据失效，需重新添加设备才能连接。操作审计只记录动作和标识，不保留草稿正文或凭据。

## 开发与部署

### 图片、语音与表情

Mac 客户端已支持按消息读取微信图片、上传图片测试、选择独立的图片理解和语音转写模型，并按联系人开启自动处理。图片按内容、服务和模型在本地持久化缓存，重复识别会复用同模型结果。微信内置与 Unicode 表情在本地解释常见用法，自定义表情包复用图片识别路径。

媒体提取与识别是两个环节，AI 接口同样需要有效文件。媒体尚未在微信下载或本地读取失败时，会保留占位及错误提示，不阻断文字采集，也可以手动补充。模型识别使用已配置且授权的服务；腾讯云会话动态接收解析文字，原始媒体仍留在 Mac。真实微信语音提取的兼容性仍需以当前来信实测为准。

### 服务结构与发布

云端后端是 Django，直接沿用 Session 与 CSRF；固定的 `/api/v1/chat/ingest` 上传和 `/api/v1/chat/device/check` 验证接口使用独立 Bearer 设备凭据。聊天数据库表独立于财务租户表，所有页面读写按当前用户过滤。入口显示、导航隐藏都不能代替后端授权。

Mac 客户端源码位于 [`clients/xiangzhi`](../clients/xiangzhi/README.md)，不包含个人聊天、密钥、数据库、习惯档案或模型登录文件。云端 Docker 镜像不包含 Mac 客户端，也不需要安装微信和 Codex。发布新增迁移，不重新初始化已有数据库、不创建默认账户，不重置原有登录、密码和财务数据。

上线前应在独立测试库核验登录、CSRF、跨账号访问拒绝、账号停用、设备撤销、上传大小限制、重传去重和原有财务流程；部署前完成加密备份，上线后校验既有表数据保留和服务健康。远程管理说明见 [2.14.0 发布说明](release-2.14.0.md)，历史设备配置与永久删除发布证据见 [2.13.1 发布说明](release-2.13.1.md)。
