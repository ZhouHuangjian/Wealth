## 02  产品目标、范围与阶段边界

*个人可独立使用，家庭在明确授权后共同使用*

产品目标：让使用者知道钱在哪里、净资产与可动用资金有多少、财富变化来自哪里、未来付款是否有缺口，以及自己的投资判断是否得到验证。管理事实、未来计划和参考估算必须分层。

| 阶段 | 必须交付的能力 |
| --- | --- |
| P0｜完整首版 | 多空间与权限；CNY/HKD/USD；境内及港美资产身份；账户与期初；统一账本；首批来源导入、去重、冲正与对账。 |
| P0｜投资与规划 | 基金股票实际业务、QDII 在途与确认、定投实例、收益日历、基础净损益与可计算范围内 XIRR；期货期权机构结算；大额目标、贷款计划、现金流预测与资金预留。 |
| P0｜产品体验 | 7+1 导航、手绘界面与低装饰模式、基础笔记与人工复盘、数据健康、站内待办、导出、备份恢复；中文电脑网页优先。 |
| P1｜管理增强 | 条件化配置与加仓规则、风险预算评估、TWR/回撤/归因、基准对照、笔记假设验证、经授权的行情/只读同步、可选 AI 与外部通知。 |
| P2｜按项立项 | 逐品种衍生品复算、复杂保证金、持仓穿透与回测、复杂公司行为、精细家庭内账户共享、公开注册及移动端专门优化。 |


### 不属于首版的能力

不托管资金，不执行银行转账、代扣、基金申购或证券订单；不进行借贷撮合、税务申报、未经授权的账户访问或行情抓取；不提供默认收益承诺。内部“确认入账”绝不代表向金融机构发起交易。


### 默认值与确认项

沿用 D1 的设计默认：邀请制；空间本位币默认为 CNY；每个用户可加入多个空间；空间建立时明确时区；原生 App 不在范围内。主题菜单名称与具体视觉参数是本版建议，不宣称已获最终确认。

> P0/P1/P2 表示业务范围；G0—G5 表示验收关卡，两者不是同一套编号。任何 P0 缺项都须显式变更范围，不能以“先做个首页”代替。

*依据：D1 §1—3、§5、§7；D4 §9、§12；D5。*


## 03  一级菜单重制与功能归属

*7 个业务入口＋1 个固定设置入口*

| 一级菜单／稳定路由 | 二级功能 | 边界 |
| --- | --- | --- |
| 财富庄园（首页）<br>/home | 净资产、可用资金、收益摘要、日历、待办与数据健康 | 总览与入口，不另建账。 |
| 资产仓库（资产）<br>/assets | 资产总览、账户、持仓、负债、借出款、其他资产、账户核对 | 维护账户、资产身份和债权债务档案。 |
| 投资集市（投资）<br>/investments | 行情与自选、交易、在途、定投、产品规则、衍生品结算 | 管理投资事实与执行进度，不执行外部订单。 |
| 收支账本（收支）<br>/cashbook | 流水、记一笔、预算、账单中心、实际还款、对账与待办 | 原始文件导入和日常资金业务的主入口。 |
| 财富规划（规划）<br>/planning | 财富目标、资金池、付款节点、还款计划、现金流、配置与规则 | 负责未来安排；实际付款引用既有事件。 |
| 投资手札（笔记）<br>/notebook | 随手笔记、交易前计划、交易后记录、原则与假设 | 保存文字判断、附件、版本和验证过程。 |
| 分析复盘（分析）<br>/analytics | 收益、净资产变化、费用、资金流、策略与纪律分析 | 量化汇总；打开同一笔记或复盘，不复制一份。 |
| 系统设置<br>/settings | 成员、数据源、产品规则配置、任务、隐私、导出、备份、安全 | 底部固定；日常导入与对账不只藏在这里。 |


### 归并规则

原“账户”并入资产仓库；“理财”拆成投资事实与未来规划；“贷借”按档案、实际收付、未来期次分工；“复盘”分为手札中的文字记录与分析中的量化视图。跨页面使用相同记录 ID 和统一详情抽屉。

菜单名称允许切换为“首页、资产、投资、收支、规划、笔记、分析”；路由与权限不随主题名称变化。本文路由均挂在 /spaces/:spaceId 下，确保当前空间始终明确。

*依据：D1 §5 的页面职责；D5 的菜单重组；本版补充稳定路由与归属规则。*


## 04  全局布局、入口与页面状态

*先保证能找、能看、能操作，再加入装饰*

| 编号 | 需求与可验证行为 |
| --- | --- |
| UX-01｜空间上下文 | 顶部常驻空间名称、切换入口、本位币/显示币种、统计日期、数据状态。切空间后清理前一空间缓存与草稿上下文；未保存内容先提示。 |
| UX-02｜高频入口 | 顶部固定“导入账单”“记一笔”“待办”。收支账本内显式列出账单中心、对账与待办；资产和投资页提供对应范围的快捷入口。 |
| UX-03｜统一详情 | 点击金额可查看构成、范围、来源、时点与缺失原因；从表格、图表、日历打开的是同一事件或账户详情。 |
| UX-04｜搜索筛选 | 空间内搜索账户、资产、事件与笔记；支持币种、日期、账户、状态筛选。全局公开产品搜索与私有数据搜索分区；不跨空间泄露结果。 |
| UX-05｜状态一致 | 所有页面有加载、无数据、无权限、失败、过期、部分完整等状态。未知不是 0；失败不是空数据；演示模式必须有持续标识。 |
| UX-06｜操作文案 | 使用“记录买入”“导入成交”“核对确认”“保存计划”。不使用“立即买入”“一键转账”等暗示外部执行的按钮。 |
| UX-07｜草稿与确认 | 支持复杂表单草稿；财务写入、冲正和批量提交显示影响预览；请求冲突要求刷新后重新确认，不静默覆盖。 |


### 屏幕适配

1440px 作为桌面设计基准；1024px 可完成首版全部核心流程。窄屏至少保证阅读、查看待办和简单记账；复杂导入映射可提示使用桌面。导航可折叠，表格在组件内滚动，页面不整体横向溢出。网页不固定为渲染图的画布比例。


### 无障碍与财务状态

正文和金额为真实文本，支持复制、键盘操作、焦点提示与 200% 缩放。涨跌同时显示正负号或文字；风险和数据错误不得仅用颜色区分。余额遮挡也覆盖图表提示、搜索预览和最近记录。

*依据：D1 §5；D4 §2、§3；D5。具体屏幕和键盘验收见附录 B。*

## 06  前端可行性与设计系统约束

*自定义外观组件＋成熟表单表格＋真实图表*

本版建议采用“手绘外壳、清晰内容”的组件方案，而非整页截图切片，也不为卡通风格重做所有复杂控件。Ant Design 官方提供全局及组件级主题变量；本项目拟据此统一控件色彩，再由自定义外壳承载木牌和纸张视觉。[W1]

| 层级／组件 | 实现约束 |
| --- | --- |
| 场景层 SceneBackdrop | 少量 WebP/PNG 插画，按需加载；不可含金额、菜单文字或真实账户信息；隐藏后功能完整。 |
| 外壳层 WoodenNav / PaperPanel | CSS 与必要 SVG 表达边框、阴影、纹理；轮廓允许轻微不规则，命中区域规则稳定。 |
| 业务层 MoneyValue / DataStatus | 数字、币种、时间、完整性与来源为 DOM 文本；共用后端指标契约；不得从图片识别金额。 |
| 控件层 DataTable / ImportWizard | 保留成熟表格、表单、日期选择、弹窗和键盘能力；主题通过封装与 Token 控制，不依赖脆弱全局 CSS 覆盖。 |
| 图表层 MetricChart | ECharts 绘制真实坐标、曲线与提示；外壳可手绘，刻度与数值不手绘；必须提供可读数据表。 |
| 交互层 EvidenceDrawer / ConfirmDialog | 统一证据查看、差异预览、冲正说明和权限检查反馈；错误比装饰更显著。 |


### 建议视觉变量

纸色 #FFF8E8，主文字 #2E2925，木色 #C79864，主强调 #437665，提示色 #A87520；盈亏与风险使用独立语义色，验证对比度后冻结。正文建议 14—16px、表格不小于 13px、关键金额 28—36px；金额采用等宽数字。


### 主题与动效

默认手绘主题，同时提供“低装饰”开关：关闭背景插画、纹理和非必要动画但保留导航结构。动效只用于反馈，约 120—200ms；尊重减少动态效果设置。首次静态装饰资源目标不超过 1.5MB，可按性能实测调整；不在本轮生成素材或代码。

## 07  财富庄园：首页与核心金额

*同一报表来源，不让首页成为第二本账*

| 编号／区域 | 首版要求 |
| --- | --- |
| HOME-01｜顶部指标 | 净资产、总资产、总负债、可动用现金、规划后可安排资金；未完整时显示“已知部分”，不伪报精确完整合计。 |
| HOME-02｜收益 | 最近完整正式收益、选定期间净损益、参考估值分别标识；不强制以今日为唯一主卡，避免 QDII 晚披露造成假零收益。 |
| HOME-03｜趋势分布 | 净资产规模曲线与投资表现曲线分开；分布可按资产、机构、币种切换，说明分母与未知项。 |
| HOME-04｜业务日历 | 显示定投、基金确认、资金到账、还款和复盘事项；同一日可有多个市场交易状态。 |
| HOME-05｜优先待办 | 未解释差额、长期在途、到期还款、缺净值/汇率优先；点击进入具体处理页，不只弹一句提示。 |
| HOME-06｜补充卡片 | 近期账户、持仓、已建目标与最近笔记；未配置就显示引导，不预设财务自由、购房或教育目标。 |


### 金额定义

净资产＝选定空间与时点下、按互斥贡献规则折算的资产－负债。账户总额与子账户、持仓明细不能重复相加；机构权益已含负债的范围也不得再减一次。

可动用现金按币种和用途展示，优先采用经核实的可提取／已交收金额，不含证券市值或授信额度。可安排资金＝可动用现金－尚未反映于机构可用额的已启用预留；同笔冻结与系统预留必须匹配去重。负数显示资金缺口。

可投资资产由用户选定组合范围；房产、备用金和期货保证金不自动视为可继续投入的现金。资金池分配是用途，不新建资产。

> 日期、空间、币种、范围、数据截止与完整性必须随指标一起返回。没有覆盖权重时，不计算看似精确的“覆盖率百分比”，改列已覆盖/未覆盖账户。

*依据：D1 FR-02、FR-07、FR-09、FR-11；D4 HOME 与金额定义。*

### 互斥计值模式

明细模式：现金、持仓及应收应付等明细共同贡献。机构权益模式：在明确范围与时点内仅以机构权益贡献，所属明细只用于展示及对账。模式切换需记录范围、日期、差异预览与操作者，不能通过切换“抹平”差额。

跨账户持仓可合并查看，但保留每个账户与批次。未知成本只阻断成本相关收益，不阻断已知份额展示；缺价格或缺汇率会使总资产不完整。

## 10  统一账本与业务不变量

*证据 → 经济事项／生命周期 → 分录与持仓 → 对账与报表*

一个经济事项可有多份证据，也可在扣款、确认、退款等阶段产生多个事件。各阶段有唯一身份和引用关系；同一资金影响只记一次。原始证据、已确认事件及分录是事实，余额和趋势是可重算投影。

| 编号 | 强制约束 |
| --- | --- |
| LED-01｜平衡 | 每个已确认事件按币种借贷平衡；跨币种通过明确桥接科目实现。借贷分录不要求普通用户手工拼接，由业务命令生成。 |
| LED-02｜事实分层 | 计划和估算不写实际分录；机构现金快照、权益快照、价格快照与本地账本分存，快照不得直接覆盖历史事实。 |
| LED-03｜重复归并 | 同源同一记录不重复；跨源同一事项只追加证据关联。不同款项即使金额和日期相同也不能直接合并。 |
| LED-04｜统一事务 | 事件、分录、持仓变化、证据关联、修订号和 outbox 同事务提交；失败不留下半笔账。 |
| LED-05｜冲正与更正 | 已过账事项不能直接删除或改写；生成冲正/替代链、理由与依赖检查；相关收益和核对结论失效后重算。 |
| LED-06｜未知处理 | 真实现金变化已证实但类别不明时进入明确清算/待分配状态；不凭空记收入调平；受影响指标显示不完整。 |
| LED-07｜贡献范围 | 同一账户、币种、日期和覆盖范围，明细与机构权益只选一套贡献；后台报表与首页采用相同选择结果。 |


### 固定统计口径

本人同空间转账、充值、投资本金往返、借入本金和还本不算生活收入/消费。信用卡消费记费用并增加负债，还款本金不重复记消费；退款关联原消费，保留退款发生日期与原消费期间。分红再投是内部收益再投资，不算组合外部投入。

不同空间不自动建立内部转账或互查凭证；首版禁止跨空间分录关联。确需分别记录时各自确认其本空间事实，不提供未经评审的跨空间合并报表。

*依据：D1 FR-03—07、FR-10—11；D2 §4、§6；D4 §4。*


## 11  账单导入、证据归并与批次冲正

*账单中心是核心业务入口，不是后台设置附件*

IMP-01：选择空间与来源 → 上传私有文件 → 解析 → 字段/账户映射 → 规范化预览 → 处理重复、转账与退款 → 确认提交 → 对账。上传或解析完成不得改变正式余额。

| 编号 | 要求 |
| --- | --- |
| IMP-02｜原始保留 | 记录文件摘要、来源账户、导入时间、解析器/映射版本、原始行号与原字段；规范化值可以追溯回证据。 |
| IMP-03｜候选匹配 | 优先稳定外部 ID；无 ID 时生成账户、币种、金额、日期及对手等候选指纹；低置信或矛盾候选交人工确认。 |
| IMP-04｜跨源合并 | 银行扣款、微信支付与喵喵分类可为同一事项的不同证据；机构记录解释资金，用户原分类和修订保留版本，不无痕覆盖。 |

| IMP-06｜并发和过期 | 提交匹配空间、映射版本、账本修订与预览摘要；出现变化返回冲突并重预览。重复点击、超时重试不重复产生资金影响。 |
| IMP-07｜撤销与冲正 | 未过账草稿可取消；已提交批次按关联和依赖预览执行。只解绑重复证据时不冲掉仍被其他来源证明的经济事项。 |
| IMP-08｜错误可操作 | 展示行级错误、中文原因、可重试状态、错误行导出与进度；未知格式进入映射/待处理，不默认成功。 |


### 支持状态必须可见

每个适配器标注“计划适配 / 样本解析通过 / 对账通过 / 已上线”，并列具体格式版本、覆盖字段与未覆盖业务。上传成功、CSV 可读或演示通过，都不能改写成“该机构已兼容”。

> 解析器升级不能重新制造交易。已确认记录的永久来源身份与 HTTP 幂等键分别维护；前者不因缓存清理或幂等记录过期而失效。

*依据：D1 FR-03、FR-11；D2 §6、§8；对旧 D4“仅重试失败行”作原子提交澄清。*

### 合成例：换汇与估值

按测试实际汇率 7.00，用 7,000 CNY 换入 1,000 USD，另付 10 CNY 费用：当时净资产仅因费用减少 10 CNY。之后 USD 估值汇率为 7.10 时，美元现金产生 100 CNY 汇率影响；这不是股票上涨收益。

### 成本和费用的统一政策

> 自动确认仅在已核实证据满足必需字段、账户匹配和规则校验时执行。预计日期到达、计划被勾选或估值出现，均不是成交证据。

### 计算政策

固定月利率 r、本金 P、期数 n 的等额本息测算：M=P×r×(1+r)^n÷[(1+r)^n−1]；r=0 时 M=P/n。等额本金逐期本金为 P/n，利息按约定期间剩余本金计算。合同年利率到期利率的换算规则显式记录；舍入与末期尾差以计划政策及机构结果校验。

> 已证实还款 520 元，其中本金 500、利息 20：现金减 520，负债减 500，净资产减 20。只有扣款证据时，不猜“500＋20”，先标待分配。

### 财富变化不等于投资收益

整体净资产变化需要区分外部收入、生活费用、投资损益、汇率/估值变化及有说明的修订。某组合的转入可影响其资金加权收益，但同一空间内部划转不增加家庭财富。


### 计算状态与可复现性

每项指标返回组合范围、期间、方法/成本版本、行情与汇率版本、账本修订、数据缺口及计算状态。XIRR 的日期基准、搜索区间、容差和多根识别在 G0 固化；短期年化显示放大效应提示。

*依据：D1 FR-06、FR-11；D2 §6；D4 PERF。本版不声称符合任何机构绩效认证。*

| 编号 | 首版要求 |

| REC-06｜待办 | 待确认、待分配、差异、缺价格/汇率、到期/失败任务汇总；按影响范围和严重程度排序，支持处理、延期、忽略理由和恢复状态。 |


### 任务与通知

JOB-01：周期扫描按空间时区生成期次；任务保存输入修订、开始/结束、重试与错误。系统恢复补扫漏项，不把补扫当成外部已支付。JOB-02：通知去重聚合，站内为首版；外部推送后续启用且默认不含敏感金额。

JOB-03：数据库 outbox 与事实同事务写入，投递可重试；重复消息依靠业务唯一键无重复效果。单调度器仍可能发生任务重叠，须锁与唯一约束保护；这一风险与 Celery 官方周期任务说明一致。[W4]

> 待办关闭不等于差异消失。忽略需留下理由；关键金额仍受缺失/冲突状态约束，不能用“已读”把未知结果改成完整。

## 27  API、金额精度与一致性契约

*同一领域命令服务全部入口*

API-01：统一前缀 /api/v1/spaces/{space_id}。每次验证会话与 Membership 后再按空间查询；URL 中的 ID 不构成授权。金额和数量为十进制字符串，响应返回 data_revision、as_of、completeness 和原因。

| 命令／资源示意 | 关键行为 |
| --- | --- |
| POST /imports；GET /imports/{id} | 上传、解析、映射、预览只产生候选；耗时任务返回可查询 ID 和进度。 |
| POST /imports/{id}/commit /reverse | 匹配预览与账本版本；提交原子性；冲正前检查证据与依赖。 |
| POST /events；POST /events/{id}/correct | 按业务类型收字段；后端生成平衡分录；普通用户不提交任意不平衡分录。 |
| GET /overview /positions /performance | 相同贡献选择与成本/估值版本；返回范围、构成、币种和数据缺口。 |
| /plans /occurrences /loans /installments | 计划操作不触发外部交易；实际确认可关联既有事件，不重复扣款。 |
| /goals /scenarios /reservations /notes | 未来方案、资金预留、笔记版本和权限清晰；关联对象必须同空间。 |
| POST /reconciliations /exports | 核对不自动调平；导出生成及下载均重新校验 Owner 权限。 |


### API-02｜幂等与冲突

入账命令携带 Idempotency-Key，按空间、调用者与命令登记；同键同请求返回原结果，同键不同请求返回 409。编辑使用 version/If-Match；预览过期或并发冲突返回 409/412 并给刷新入口。永久来源唯一约束独立于 HTTP 幂等记录。


### DAT-03｜精度与数据库

金额候选 NUMERIC(38,12)，数量/价格/汇率候选 NUMERIC(38,18)；Python Decimal 从原始字符串创建，运算精度与量化位置显式设置，不先转 float。原 D2 的 160 位中间精度保留为 G0 压测候选，不当作已证明足够的保证。[W2]

分录跨行平衡需要提交入口/延迟约束等保证，不能靠单行 CHECK。并发锁顺序、唯一约束、事务失败和修订投影必须测试。错误统一 code、中文 message、字段错误、可重试标记及脱敏 request_id。

*依据：D2 §6、§8；W2 Decimal 文档。接口为建议契约，未在本轮实现。*

## 附录 A  合成账务与资金占用算例

*用于开发和验收，不代表用户资产或真实产品费率*


### A1｜基金全生命周期

期初银行 10,000；申购 1,000，费用 10，确认净值 2.00、份额 495；赎回净值 2.04、费用 5。管理取得成本为含买入费的 1,000。

| 阶段 | 现金 | 在途/应收 | 持仓价值 | 总资产 |
| --- | --- | --- | --- | --- |
| 期初 | 10,000.00 | 0.00 | 0.00 | 10,000.00 |
| 申购已扣未确认 | 9,000.00 | 1,000.00 | 0.00 | 10,000.00 |
| 确认 495 份 | 9,000.00 | 0.00 | 990.00 | 9,990.00 |
| 正式净值 2.02 | 9,000.00 | 0.00 | 999.90 | 9,999.90 |
| 赎回确认，尚未到账 | 9,000.00 | 1,004.80 | 0.00 | 10,004.80 |
| 实际到账 | 10,004.80 | 0.00 | 0.00 | 10,004.80 |
