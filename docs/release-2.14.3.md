## EST-012 / P1：已知正式收益被失效参考遮挡

用户症状：首页“最近基金收益更新”显示参考基准不一致、金额空缺，但同一持仓已有可用的最近正式收益。预期是保留参考失效原因并显示正式结果及其所属日期；不是将10/12收益搬到10/13的“今日收益”。

证据分两层：[19:40公开响应对比](audits/evidence/2026-10-13/estimate-funding-2142/sina-baseline-change-1940.md)确认五只基金的基准从10/09前移至10/12，455个估值点没有更新，最后报价仍为05:04；[19:44生产只读复现](audits/evidence/2026-10-13/estimate-formal-2143/pre-fix-readonly.json)确认017641、019305、019172、021778、270042均有10/12正式NAV及同日可用最近正式收益，独立更新区却仍为`reference_baseline`。只读记录省略私账金额，无登录、手动刷新或生产写入。来源证据不构成独立正式净值来源。

根因位于[fund_return_updates._holding_update](../backend/wealth/fund_return_updates.py)：2.14.2只有正式NAV晚于来源基准或同日正式值不同才进入正式展示；两边基准同步前移后，旧报价在后续价格/涨幅关系校验中被正确拒绝，却直接返回空缺，没有继续取独立正式结果。参考一致性校验应保留；问题在读侧分支，不是需要放宽校验或重算账务。

## 最小修复与接口影响

业务规则唯一维护于[领域模型§14.3](domain-model.md#143-最近基金更新有明确基准的海外时段参考2142已部署限定验证见发布记录)，字段见[API§21.1](api-contract.md#211-最近基金收益更新2142)，操作见[RUNBOOK§8.9](RUNBOOK.md#89-最近基金收益更新与参考来源)。

- 仅`reference_baseline/reference_time/reference_date/reference_refresh`四类参考失败可以尝试正式回退。同账户同产品的`latest_confirmed_return`原币金额必须非null，NAV日精确等于最新获准正式NAV日；0是有效结果。有效参考仍优先展示估算。
- 复用正式链的金额、实际比较基准、NAV归属日、收益率、份额来源和收益日FX。身份不符、相关NAV冲突、未核实交易日期、原持仓待核对仍阻断；无对应正式结果继续留空。正式公布时间未知仍为null，记录时间不能冒充公布时间。
- 兼容增加`reference_unavailable_reason_code/reference_unavailable_message`，保留原参考失败原因。提示说明正式与参考覆盖区间不一定相同，不相加。缺FX保留原币及`native_status=formal`，折算金额为null。

范围仅为现有“最近基金收益更新”的只读结果。无数据库迁移、来源开关变更、估值阈值放宽、自动写Price、账务/份额改写或历史投影重建。原今日汇总、收益日历、净资产和定投扣款规则保持原计算入口；没有自动为用户选择补足账户。
